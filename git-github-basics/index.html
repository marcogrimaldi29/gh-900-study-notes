Version Control Fundamentals

Purpose & Benefits of Version Control

A version control system (VCS) records changes to files over time so you can recall specific versions later, understand what changed and why, and collaborate without overwriting each other's work.

ⓘ What Is Git?

Per GitHub Docs: Git is a distributed version control system (DVCS) — every contributor's clone is a full-fledged repository with complete history, so you can work offline and there is no single point of failure.

Key Benefits to Know

  • Complete history & traceability — every change is recorded with an author, timestamp, and message
  • Revert & recover — roll back to any previous working state if something breaks
  • Parallel work via branches — multiple people develop features simultaneously without conflict
  • Collaboration at scale — merge contributions from many developers into one project
  • Accountability — git blame and history show who changed what and when
  • Experimentation — try ideas on a branch and discard them safely if they don't work

Centralized vs. Distributed Version Control

TypeHow It WorksExamples
Centralized (CVCS)One central server holds the repository; clients check out files. Offline work is limited.Subversion (SVN), CVS, Perforce
Distributed (DVCS)Every clone is a full repository with complete history. Work offline, commit locally, sync later.Git, Mercurial

Git vs. GitHub — Know the Difference

This distinction is directly and frequently tested. Git is the tool; GitHub is a cloud platform built around it.

GitGitHub
What it isOpen-source, distributed version control softwareCloud-based hosting platform for Git repositories
Where it runsLocally on your computer (command line or GUI)On the web (github.com) — SaaS
Created byLinus Torvalds (2005)GitHub, Inc. (2008), now part of Microsoft
AddsCommits, branches, merges, historyPull requests, issues, Actions, collaboration, access control, social features
Needs internet?No — fully functional offlineYes — it's a hosted service
💡 Memory Hook

Git = the version-control engine on your machine. GitHub = the place where you host, share, and collaborate on Git repositories. You can use Git without GitHub, but GitHub requires Git under the hood. (Alternatives that also host Git include GitLab and Bitbucket.)

Key Git Concepts — Repositories, Commits & Branches

Core Terminology

  • Repository (repo): a project's folder containing all files and the complete history of changes, tracked by Git in a hidden .git directory
  • Commit: a snapshot of your changes at a point in time, with a unique ID (SHA hash), author, and message. Commits form the project history
  • Branch: a movable pointer to a line of development. The default branch is usually main. Branches let you work in isolation
  • Merge: combining the changes from one branch into another
  • Clone: a full local copy of a remote repository, including all history
  • Fork: your own server-side copy of someone else's repository under your account
  • Remote: a version of the repo hosted elsewhere (e.g. origin on GitHub)
  • Staging area (index): where you place changes with git add before committing them

The Everyday Git Workflow

CommandWhat it does
git initCreate a new local repository
git clone <url>Copy a remote repository (with history) to your machine
git add <file>Stage changes for the next commit
git commit -m "message"Record staged changes as a snapshot
git pushUpload local commits to the remote (e.g. GitHub)
git pullFetch remote changes and merge them into your branch
git branch / git checkout -bList branches / create and switch to a new branch
git merge <branch>Combine another branch into the current one
⚠ Exam Tip — Clone vs. Fork

A clone is a local copy on your machine. A fork is a copy on GitHub under your own account, typically used to contribute to a project you don't have write access to. You usually fork on GitHub, then clone your fork to work locally.

Working with GitHub

Accounts, Organizations & Enterprise

GitHub offers three account types. Understanding the hierarchy — personal → organization → enterprise — is exam-relevant.

Account TypePurpose
Personal accountAn individual identity on GitHub. Owns repositories and can belong to organizations. Every person has exactly one.
OrganizationA shared account for teams and companies. Groups people into teams with granular access to shared repositories. Owned by one or more admins.
Enterprise accountA top-level container for managing multiple organizations, centralized billing, and policy across a large company.

Plans (High Level)

  • GitHub Free — unlimited public and private repos, core features, for individuals and organizations
  • GitHub Team — paid per-user plan for organizations; adds advanced collaboration and more Actions/Packages allowances
  • GitHub Enterprise — adds enterprise-grade security, compliance, SAML SSO, and centralized administration. Available as Enterprise Cloud (hosted) or Enterprise Server (self-hosted)

The GitHub Flow

The GitHub Flow is a lightweight, branch-based workflow. Memorize the steps and their order.

The Steps, In Order

  • 1. Create a branch — branch off main so your work is isolated from the stable code
  • 2. Make changes & commit — add commits with clear messages describing each change
  • 3. Open a pull request (PR) — propose your changes and start a discussion/review
  • 4. Review & discuss — collaborators review, comment, and request changes; CI checks run
  • 5. Merge the pull request — once approved, merge into main
  • 6. Delete the branch — clean up the merged branch
⚠ Must-Know — GitHub Flow

The very first step is always create a branch, and the pull request is the mechanism for review before merging to main. Expect a question that asks you to put these steps in the correct sequence or identify the purpose of the pull request.

Markdown for Clear Communication

Markdown is a lightweight markup language used to format issues, pull requests, comments, READMEs, wikis, and discussions. GitHub uses GitHub Flavored Markdown (GFM).

💡 Study Tip — Task Lists & References

Task lists (- [ ]) create checkable checkboxes, and typing # followed by a number auto-links to an issue or PR. These GFM features power issue tracking and are commonly referenced on the exam.

GitHub Desktop & GitHub Mobile

When to Use Each

  • GitHub Desktop — a free GUI app for Windows/macOS that lets you clone, commit, branch, and open pull requests without the command line. Ideal for those less comfortable with Git CLI, and for visualizing diffs and history.
  • GitHub Mobile — iOS/Android apps to stay productive on the go: triage and respond to notifications, review and comment on pull requests, manage issues, and merge PRs. Not intended for heavy code editing.
  • github.dev / Codespaces — browser-based editing options (covered under Modern Development) for when you need to edit code without a local setup.
ⓘ Exam Framing

Questions typically ask which tool fits a scenario: "review a PR from your phone" → GitHub Mobile; "commit and branch with a visual interface, no terminal" → GitHub Desktop; "quick edit in the browser" → github.dev.
